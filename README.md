# Code64
a 6502/Python hybrid assembler for c64 cross development

Code64 is a multi-pass 6502 assembler for the Commodore 64. Every expression is a Python expression, and assembly code can be generated by Python functions, so the full power of Python is available while writing 6502 code.

- standard 6502 instruction set, with automatic zero page addressing
- Python expressions, f-strings and lambdas in operands and directives
- generators: Python functions that return assembly code
- local labels, zero page variable allocation, repeat blocks
- PETSCII and screen code text encodings
- import of source files, Python files, binary files, SID music and images
- built-in symbols for the C64 hardware (VIC, SID, CIA, KERNAL, BASIC)
- outputs a `.prg` file, ready to load in an emulator or on a real C64


## Installation

Code64 requires Python 3.8 or later, and installs with [pipx](https://pipx.pypa.io):

```bash
git clone https://github.com/Morty40/Code64.git
cd Code64
./install.sh
```

This installs the `code64` command. Run `./install.sh` again to update after pulling changes, and `./uninstall.sh` to remove it.

Code64 can also run directly from the source folder, without installing:

```bash
./code64/main.py -a hello.asm -o hello.prg
```


## Usage

```
code64 -a <asmFile> -o <outFile>
```

| Option | Description |
|---|---|
| `-a <asmFile>` | the source file to assemble |
| `-o <outFile>` | the `.prg` file to write. Without `-o` the source is assembled and checked, but nothing is saved |
| `-h` | print the usage |

The output file is only written when there are no errors. Errors and warnings are printed with file name and line number, and the exit code is 1 on errors. After a successful assembly, Code64 prints the memory range used, the address of every global label, and a map of the 256 memory pages.

The `.prg` file starts with the 2-byte load address (the lowest address used), followed by every byte up to the highest address used. Gaps are filled with zeros.

A Makefile rule for building `.prg` files:

```make
%.prg: %.asm
	code64 -a $< -o $@
```


## Example

```
; hello.asm - prints a message, makes the border red, and returns to BASIC

            @basicStart()
            @basicSys(10, start)    ; 10 SYS2061
            @basicEnd()

start:      ldx #0
_loop:      lda message,x
            beq _done
            sta $0400,x             ; screen memory
            inx
            bne _loop
_done:      lda #2                  ; red
            sta VIC_BORDER_COLOR
            rts

            .encoding ENCODING_SCREEN_UPPER
message:    .string "HELLO WORLD"
```

```bash
code64 -a hello.asm -o hello.prg
```

Load `hello.prg` in an emulator such as [VICE](https://vice-emu.sourceforge.io), and type `RUN`.


## Syntax

### Lines and comments

Each line holds one statement: an instruction, a directive, an assignment or a generator, optionally preceded by a label. Comments start with `;` and run to the end of the line. Indentation is free.

```
label:      lda #1          ; comment
            .byte 1, 2, 3
value = 42
            @nop(3)
```

### Instructions

All 56 documented 6502 instructions are supported. Mnemonics are written in lowercase.

| Address mode | Syntax |
|---|---|
| implied | `rts` |
| accumulator | `asl` |
| immediate | `lda #value` |
| zero page / absolute | `lda address` |
| zero page,x / absolute,x | `lda address,x` |
| zero page,y / absolute,y | `ldx address,y` |
| indirect | `jmp (address)` |
| indexed indirect | `lda (address,x)` |
| indirect indexed | `lda (address),y` |
| relative | `bne label` |

The zero page form is chosen automatically when the address is below `$100` and the instruction has a zero page form. A branch to a destination out of range is an error, and `jmp (address)` with the address on a page boundary (`$xxff`) gives a warning, as the 6502 does not cross the page.

### Numbers

| Format | Example |
|---|---|
| decimal | `255` |
| hexadecimal | `$ff` or `0xff` |
| binary | `%11111111` or `0b11111111` |

`%` is also the Python modulo operator. Directly after a number, a name or a `)`, it is modulo: `7 % 4`, `x %10`. Elsewhere, `%` followed by binary digits is a binary number: `lda #%1010`.

### Labels

A label is a name followed by `:`, and gets the value of the current address. A label can be on a line of its own, or in front of a statement. Each label can only be defined once.

```
start:      lda #0
loop:
            jmp loop
```

Labels starting with `_` are local. A local label belongs to the global label before it, so the same local name can be reused under different global labels:

```
clear:      ldx #0
_loop:      sta $0400,x
            inx
            bne _loop       ; clear's _loop
            rts

fill:       ldx #0
_loop:      sta $d800,x
            inx
            bne _loop       ; fill's _loop
            rts
```

The symbol `_` on its own is the current address. Assigning to it moves the current address, like `.org`:

```
            .word _ + 2     ; the address after this word
            _ = $2000       ; same as .org $2000
```

### Assignments

`name = expression` assigns the value of a Python expression to a symbol. Any Python value can be assigned, not only numbers.

```
SCREEN = $0400
colors = [0, 11, 12, 15, 1]
squares = [x * x for x in range(16)]
            .byte colors[2], squares[3]
```

#### Constants

Symbols in all upper case, such as `SCREEN` or `MAX_SPEED`, are constants: once a constant has a value, it can't be assigned a different value. Doing so is an error, and the constant keeps its first value. Symbols with any lower case letters, such as `speed` or `maxSpeed`, are variables, and can be assigned again freely.

```
MAX_SPEED = 4
MAX_SPEED = 4               ; ok, the same value
MAX_SPEED = 5               ; error: Constant "MAX_SPEED" cannot be changed from 4 to 5
speed = 1
speed = 2                   ; ok, a variable
```

The built-in symbols, such as `VIC_BORDER_COLOR`, are constants too, so they cannot be given a different value by mistake.

Use a variable for a value that changes, for example in each round of a `.repeat` block. Also use a variable for a value calculated from labels that come later in the source, such as `codeSize = end - start`: while the assembler passes settle, such a value can change, which is an error for a constant.

### Expressions

Operands and directive arguments are Python expressions, evaluated with all symbols (labels and assignments) as variables. Symbols can be used before they are defined, as Code64 assembles in multiple passes.

```
            lda #lo(message)
            ldx #hi(message)
            .byte 1 if DEBUG else 0
            .byte len(message), max(squares)
```

Besides the Python built-ins, these are available:

| Symbol | Description |
|---|---|
| `_` | the current address |
| `lo(x)`, `hi(x)` | the low and high byte of a 16-bit value |
| `ord(char)`, `chr(value)` | convert between a character and its value, in the current text encoding |
| `sin`, `cos`, `pi`, `floor`, ... | everything from Python's `math` module |
| `ENCODING_...` | the text encodings, see `.encoding` |

Strings in double quotes are Python f-strings, so `{expression}` inside a string is replaced with its value:

```
version = 2
            .text "VERSION {version}"
```

### Generators

A line starting with `@` is a generator: a Python expression that returns assembly source code as a string. The code is assembled in place of the generator line. Generators are Python functions, typically defined in a Python file and imported with `.import`.

```python
# macros.py
def delay(n):
    return f"""
        ldx #{n}
_loop:  dex
        bne _loop
    """
```

```
            .import "macros.py"
            @delay(100)
            @delay(200)
```

Local labels in the generated code get their own scope for each call, so a generator can be used any number of times. Generator arguments can be any Python expression, including labels and keyword arguments: `@jump(address=start)`.


## Directives

Directives start with a `.`, followed by the name and the arguments, separated by commas. Arguments are Python expressions, so names of files and symbols are written as strings.

### Location

#### .org
```
.org address
```
Sets the current address, where the following code and data is stored. The default is `$1000`.

#### .align
```
.align n
```
Advances the current address to the next multiple of `n`. Use `.align 256` to place data at the start of a page.

### Data

#### .byte
```
.byte value[, value, ...]
```
Stores bytes. Values from -128 to 255 are allowed.

```
            .byte 1, $02, %11, -1       ; 01 02 03 ff
```

#### .word
```
.word value[, value, ...]
```
Stores 16-bit words, low byte first. Values from -32768 to 65535 are allowed.

```
            .word $1234                 ; 34 12
```

#### .text
```
.text "string"[, "string", ...]
```
Stores strings, using the current text encoding.

#### .string
```
.string "string"[, "string", ...]
```
Like `.text`, but each string is followed by a zero byte.

```
            .encoding ENCODING_SCREEN_UPPER
            .string "ABC", "DEF"        ; 01 02 03 00 04 05 06 00
```

#### .bits
```
.bits "pattern"
```
Stores a bit pattern, 8 bits per byte. `0` and space are 0 bits, `1` and `#` are 1 bits, which makes it easy to draw characters and sprites:

```
            .bits "  ####  "            ; 3c
            .bits " ##  ## "            ; 66
            .bits "00011000"            ; 18
```

#### .bytefill
```
.bytefill n[, "lambda"]
```
Stores `n` bytes. Without the second argument the bytes are zero. With it, byte `x` is the value of the lambda, written as a string without the `lambda` keyword:

```
            .bytefill 4                 ; 00 00 00 00
            .bytefill 4, "x: x * 2"     ; 00 02 04 06
sine:       .bytefill 256, "x: int(128 + 127 * sin(x / 128 * pi))"
```

#### .wordfill
```
.wordfill n[, "lambda"]
```
Like `.bytefill`, but stores 16-bit words.

### Text encoding

#### .encoding
```
.encoding encoding
```
Sets the text encoding used by `.text`, `.string`, `ord()` and `chr()`. The encoding stays in effect until the next `.encoding`.

| Encoding | Description |
|---|---|
| `ENCODING_SCREEN_UPPER` | screen codes, upper case and graphics character set (default) |
| `ENCODING_SCREEN_MIXED` | screen codes, lower and upper case character set |
| `ENCODING_PETSCII_UPPER` | PETSCII, upper case and graphics character set |
| `ENCODING_PETSCII_MIXED` | PETSCII, lower and upper case character set |

Use screen codes for text written directly to screen memory, and PETSCII for text printed with the KERNAL. Note that the built-in BASIC generators switch the encoding to PETSCII.

### Zero page variables

#### .zpbyte
```
.zpbyte "name"[, "name", ...]
```
Allocates a byte in the zero page for each name, and defines the name as a label with its address. Addresses are allocated from `$02` and up, as `$00` and `$01` are used by the CPU port.

```
            .zpbyte "count", "index"    ; count = $02, index = $03
            lda count
```

#### .zpword
```
.zpword "name"[, "name", ...]
```
Like `.zpbyte`, but allocates two bytes for each name, for example for pointers used with `(address),y`.

### Files

#### .import
```
.import "file"
```
Imports a file, with the path relative to the folder of the main source file. A `.py` file is executed as Python, so its functions and variables become available to expressions and generators. Any other file is assembled as source code, in place of the `.import` line.

```
            .import "macros.py"
            .import "music.asm"
```

#### .binary
```
.binary "file"
```
Stores the contents of a binary file, with the path relative to the folder of the main source file.

#### .music
```
.music "file", "prefix"
```
Stores the music data from a SID file (PSID format), without the header. The symbols `prefix_LOAD`, `prefix_INIT` and `prefix_PLAY` are defined with the load, init and play addresses of the music. The data must be stored at its load address:

```
            .org MUSIC_LOAD
            .music "song.sid", "MUSIC"
            ...
            jsr MUSIC_INIT
```

The path is relative to the current working folder.

#### .sprite, .bitmap
```
.sprite "file", bitsPerPixel
.bitmap "file", bitsPerPixel
```
Experimental. Stores an image from an 8 bits per pixel BMP file, with a width that is a multiple of 8. The image is converted into single colour sprites of 24×21 pixels, 64 bytes each, where every non-zero pixel is a set bit. Both directives currently do the same conversion, and the `bitsPerPixel` argument is not used yet. The path is relative to the current working folder.

### Repetition

#### .repeat, .endr
```
.repeat "name", count
...
.endr
```
Assembles the lines up to `.endr` `count` times. The symbol `name` counts from 0 to `count - 1`. Repeat blocks can be nested.

```
            .repeat "row", 4
            .repeat "column", 4
            .byte row * 16 + column
            .endr
            .endr
```

### Python

#### .py
```
.py "statement"
```
Executes a Python statement, for example to define a function.

```
            .py "def double(x): return x * 2"
            .byte double(21)
```

### Messages

#### .print
```
.print value[, value, ...]
```
Prints values to the terminal. As the source is assembled in multiple passes, the values are printed once per pass.

#### .warning
```
.warning "message"
```
Reports a warning. Assembly continues.

#### .error
```
.error "message"
```
Reports an error. The output file is not written.


## Built-in symbols

The Python files in `code64/imports/` are imported automatically, and define symbols for the C64 hardware and a set of generators. The upper case symbols are [constants](#constants):

| File | Contents |
|---|---|
| `basic.py` | BASIC ROM addresses and tokens, and generators for a BASIC start line: `basicStart()`, `basicSys(lineNumber, address)`, `basicRem(lineNumber, text)`, `basicEnd()` |
| `cia.py` | CIA 1 and 2 registers, `CIA1_...` and `CIA2_...` |
| `cpu.py` | the CPU port `CPU_IO_PORT`, and generators: `nop(n)`, `ldax(value)`, `lday(value)`, `ldxy(value)`, `stax(address)`, `stay(address)`, `stxy(address)` |
| `kernal.py` | KERNAL ROM routines, `KERNAL_ROM_...` |
| `keyboard.py` | keyboard matrix codes, `KEYBOARD_CODE_...` |
| `sid.py` | SID registers, `SID_...` |
| `stack.py` | `STACK_ADDRESS`, and generators: `pushRegisters()`, `pullRegisters()`, `storeRegisters(restore)`, `restoreRegisters()` |
| `std.py` | `CHAR_ROM` |
| `vector.py` | interrupt vectors, `INTERRUPT_VECTOR_...` |
| `vic.py` | VIC-II registers, `VIC_...` |

For example `@ldax(message)` loads the address of `message` into a (low byte) and x (high byte).


## Passes, warnings and errors

Code64 assembles the source repeatedly, up to 9 passes, until the output no longer changes. This resolves forward references, and lets the size of instructions depend on labels defined later in the source. Errors are reported from the final pass only.

Warnings do not stop the output from being written. They are given when:
- a memory location is written more than once
- a float value is truncated to an integer
- `jmp (address)` has its address on a page boundary

```bash
cd code64
make test
```
